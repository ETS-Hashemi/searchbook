# Chapter 22 — Mixed-Integer Linear Programming for Planning (priority Medium; Week 11)
File Overleaf/chapters/ch22-milp.tex, label ch:ch22. Algorithm template. Target 11-13 pages.
Anchors: Schouwenaars, De Moor, Feron & How, ECC 2001; Richards & How, ACC 2002; Yu & LaValle, T-RO 2016 (MAPF as ILP); Boyd & Vandenberghe 2004 / Nocedal & Wright 2006 (LP background); Borrelli et al. 2017 (hybrid MPC).
Must cover: linear programs recap (variables, linear objective, linear constraints, the simplex/interior-point idea and the polyhedron geometry from ch:appB); INTEGER and binary variables and what they buy (choices, "either-or", on/off, assignment); the BIG-M trick for OBSTACLE AVOIDANCE, derived carefully: for a rectangular obstacle [x_min,x_max]x[y_min,y_max] and time step k, binary variables b_{k,1..4} with constraints x_k <= x_min + M b_{k,1}, x_k >= x_max - M b_{k,2}, y_k <= y_min + M b_{k,3}, y_k >= y_max - M b_{k,4}, sum_j b_{k,j} <= 3 (at least one side holds), with a figure, the meaning of M and why a too-large M hurts numerically; INTER-VEHICLE separation with the same trick (|p^i_k - p^j_k|_inf >= d_min via four binaries per pair per step) and the growth in the number of binaries (a table: agents x steps x binaries); the full formulation of a minimum-time (or minimum-fuel) multi-vehicle trajectory problem with the double-integrator dynamics as linear equality constraints, input bounds, and 1-norm/inf-norm objectives linearised with auxiliary variables; BRANCH-AND-BOUND intuition (LP relaxation, branching on a fractional binary, bounding, a small tree figure) and why solve time is exponential in the worst case; solving with scipy.optimize.milp (HiGHS) - a complete listing that solves a 2-vehicle instance and a figure of the resulting trajectories from the code; a worked example table (variables, constraints, binaries, solve time); MAPF as an integer program (time-expanded flow formulation of Yu & LaValle, sketched: one flow per agent on the time-expanded graph with capacity-one vertices and anti-swap constraints) and how it compares to CBS (exact, but scales differently); cost of exactness: a generated experiment of solve time vs number of vehicles and horizon length (pgfplots), with the honest conclusion of when MILP is worth it (small, safety-critical, offline problems; verifying heuristics; scheduling) and when it is not (online, large swarms); implementation notes (tight M, symmetry, time discretisation, warm starts, time limits and incumbents); pitfalls (M too large, corner cutting between time steps, forgetting that obstacle avoidance holds only at the sampled instants, infeasible formulations that give no diagnostic); drone box (MILP as the offline reference solution against which the hybrid planner's heuristics are benchmarked in ch:ch25, and as a scheduler for take-off/landing slots); 7-8 exercises incl. a coding exercise (formulate and solve a 3-vehicle MILP with an obstacle) and a modelling exercise.
