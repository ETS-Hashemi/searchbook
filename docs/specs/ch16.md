# Chapter 16 — Rapidly-Exploring Random Trees (priority High; Week 8)
File Overleaf/chapters/ch16-rrt.tex, label ch:ch16. Algorithm template. Target 13-15 pages.
Anchors: LaValle, "Rapidly-exploring random trees: a new tool for path planning", TR 98-11, Iowa State 1998; LaValle & Kuffner, "Randomized kinodynamic planning", IJRR 2001; Kuffner & LaValle, RRT-Connect, ICRA 2000; LaValle, Planning Algorithms, 2006 (ch. 5); Kavraki et al., PRM, 1996 (contrast).
Week 8: "Sampling, steering, collision checks, path quality in continuous space. Implement RRT* or use a library in a 3D obstacle field. Compare to grid A*. Milestone: you can choose between graph search and sampling-based planning."
Must cover: why grids fail in high-dimensional or large continuous spaces (curse of dimensionality; a table of grid sizes for 2D/3D/6D); the configuration space X, X_free, X_obs from ch:ch02; the RRT primitives with exact definitions: Sample (uniform in X, with goal bias probability p_goal), Nearest (Euclidean nearest tree vertex), Steer (move at most step size eta toward the sample), CollisionFree (segment check by subdivision, with the resolution argument); the algorithm with pseudocode; the VORONOI BIAS explanation of why the tree explores quickly (figure: a tree and the Voronoi regions of its vertices); a worked example on a 2D map with two rectangular obstacles: the tree after 50, 200, 1000 iterations (three-panel generated figure from the code) and the extracted path; properties: probabilistic completeness (statement; proof idea; the role of eta and goal bias), NOT optimal (figure showing a jagged path far from the shortest one; and the theorem of Karaman-Frazzoli that RRT converges to a non-optimal path almost surely, stated as a pointer to ch:ch17); RRT-Connect (two trees, the Connect heuristic, greedy extension) with pseudocode and a comparison of iterations to solution vs plain RRT (generated data); kinodynamic RRT in one section (sample controls, integrate, the double-integrator drone from ch:ch02; why Nearest is harder with dynamics); collision checking for drones (sphere vs axis-aligned boxes, segment-sphere tests from ch:ch02, conservative inflation); nearest-neighbour data structures (kd-trees, the O(n) naive cost vs O(log n)); path post-processing: shortcutting and smoothing with pseudocode and a figure; 3D: an example in a 3D obstacle field (generated figure, projected or 3D pgfplots) and how the code changes (nothing but the sample dimension); a comparison table grid A* vs RRT vs RRT* (completeness, optimality, memory, anytime behaviour, dynamics, when to prefer which); implementation notes (random seeds, step size, goal region radius, resolution of collision checks, maximum iterations); pitfalls (too large eta skips thin obstacles, goal bias too high makes the tree greedy and stuck, testing only vertices and not segments, forgetting the goal region); drone box (RRT as the continuous 3D planner when the grid is too coarse or the space too large; how a global grid plan and a local RRT can be combined); 8 exercises incl. the Week-8 coding exercise (RRT/RRT* in a 3D obstacle field, compare to grid A*) and a proof exercise on probabilistic completeness.
